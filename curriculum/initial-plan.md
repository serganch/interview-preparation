# Initial Preparation Plan

The curriculum should be adaptive rather than a fixed list of topics.

## Phase 1 — Baseline Assessment

Determine the candidate's current level through a combination of:

- technical questions
- system-design questions
- architecture discussions
- code-review exercises
- AI-assisted development exercises

Identify areas that are already strong and areas that need work.

Do not spend significant time on topics where the candidate already demonstrates strong competence.

## Phase 2 — Targeted Technical Preparation

Based on the assessment, create a prioritized list of gaps.

For each gap:

1. Explain the relevant concepts.
2. Give a practical problem.
3. Ask the candidate to solve it.
4. Review the solution.
5. Discuss alternatives and trade-offs.
6. Revisit the topic later if necessary.

## Phase 3 — AI-Assisted Development

Use a real software project as a training environment.

The candidate should practice the complete workflow:

requirements → decomposition → agent task → implementation → review → testing → correction → documentation.

The project should be complex enough to expose realistic engineering problems but small enough to remain manageable.

## Phase 4 — Interview Simulation

Introduce increasingly realistic interview exercises.

The candidate should practice:

- clarifying requirements
- identifying constraints
- proposing architecture
- discussing alternatives
- estimating scale
- identifying bottlenecks
- discussing failure modes
- explaining trade-offs

The mentor should behave like an interviewer rather than immediately helping.

## Phase 5 — Continuous Reassessment

The curriculum should evolve according to observed weaknesses.

Maintain a distinction between:

- known strengths
- developing skills
- unresolved gaps
- topics requiring repetition
